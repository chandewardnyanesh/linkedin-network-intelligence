LinkedIn Network Intelligence Skills

Twelve open-source Claude Agent Skills that research, score and manage a LinkedIn professional network — an ICP builder, candidate discovery, a configurable 100-point scoring engine, a networking CRM, lead intelligence and weekly funnel reporting.

It drafts and records. It never sends. No scraper, no browser driver, no session cookie, no LinkedIn credential.

What it is

LinkedIn Network Intelligence Skills is an MIT-licensed bundle of twelve Agent Skills plus a root workflow. It turns LinkedIn from a feed into a researched network: you define who is worth knowing, it finds and ranks candidates from sources you can point at, stores them with provenance, drafts the notes, tracks the relationships, and reports the funnel.

It runs on Python 3.12+ with two dependencies. There is no hosted service, no account to create and no API key.

Why it refuses to automate

Most LinkedIn tooling works by holding a li_at session cookie or driving a logged-in browser. This bundle does neither, and the restriction is enforced in code rather than promised in documentation:

  • The SourceKind enum has no member for a scrape or a browser run, so a scraped record cannot be represented in the data model.
  • No HTTP client — requests, httpx, aiohttp, urllib3 — is imported anywhere in the package, and a test asserts it.
  • Playwright, Selenium, Puppeteer and webdriver are not imported either, also asserted by test.
  • Eleven prohibited rules load from configuration that refuses to load if one is removed.
  • 33 prohibited request phrasings are refused by a classifier with regression tests, including the softened forms: "spread these over three days so it looks organic", "how many can I send before I get flagged", "warm up the account first".

Every invitation, message, comment and follow is performed by you, by hand, in LinkedIn. The bundle prepares the work and records what you did.

Install

git clone https://github.com/chandewardnyanesh/linkedin-network-intelligence.git
cd linkedin-network-intelligence
pip install -r requirements.txt
python -m lni config-check   # what loads, and what each skill needs from you
python -m lni init           # create the store

For Claude Code, add the repository as a plugin — it ships .claude-plugin/plugin.json — or copy skills/* into ~/.claude/skills/. Each skill directory is independently installable. Full instructions, including importing into other Agent Skills hosts and the PostgreSQL backend, are in INSTALLATION.md.

What makes the output trustworthy

Four disciplines, enforced as validators rather than documented as intentions:

  • A component with no inputs abstains. It scores zero and says so. A midpoint is a guess that reads like a measurement.
  • Every point carries evidence. A scored component with no observation behind it cannot be constructed.
  • Observations and predictions are separate fields. A confident propensity band with no usable observation cannot exist.
  • A metric that cannot be sourced is unavailable, with the reason. Never estimated, never interpolated. The setting that would allow estimation refuses to load.

A worked consequence: a candidate who is a perfect ICP match but has no observable activity scores around 30 and is told "strong ICP fit, but nothing observed yet — the gap is in what we know, not in who they are." A system that scored them 70 would be more flattering and less useful.

Common questions

Does it automate LinkedIn connection requests?

No, and it will refuse to. It prepares invitation drafts and a review list with the profile URLs in order; you send them yourself inside LinkedIn, then tell it which went out and it records them. A request to automate sending is refused under the rule no_automated_invitations and written to an audit trail.

Does it scrape LinkedIn profiles?

No. There is no scraper, no browser driver and no LinkedIn credential. The SourceKind enum has no member for a scrape, so such a record cannot be represented in the data model at all, and tests assert that no browser-automation library or HTTP client is imported.

Does it need my LinkedIn password or session cookie?

No, and there is no environment variable to supply one. A request to use a li_at session cookie or an unofficial endpoint is refused under no_unauthorised_api.

Where does its data come from?

Profile URLs you paste, CSVs you build, your own LinkedIn data export, your own analytics export, public company websites, professional directories, publications, event listings, referrals, rosters you exported yourself, and official LinkedIn APIs where you hold authorised access. Every record carries its source and a verification date, or it cannot be created.

How do I score LinkedIn connections?

On a configurable 100-point framework with six components: ICP relevance 25, observable activity 15, meaningful engagement signals 20, content-topic alignment 15, professional influence 10, business opportunity 15. Each component reports its own evidence and confidence, and the output carries a priority class and a recommended next action.

Is follower count used to rank people?

Barely, and deliberately. Audience size contributes at most 30% of the professional-influence component — three points of a hundred on the default weighting — on a logarithmic scale, and the configuration refuses a cap above 50%. What counts instead: publishing regularly, speaking at events, maintaining something others use, being cited, and holding a role with visible decision scope.

What is an Ideal Connection Profile?

The networking equivalent of an Ideal Customer Profile: a definition of who is worth connecting with, specific enough that two people looking at the same profile would agree whether it matches. Several coexist here across eight purposes, each with exclusion criteria and observable engagement signals.

Will it help me pace outreach to stay under LinkedIn's limits?

No. Pacing to avoid detection is refused under no_detection_evasion. If the real question is how much outreach is sustainable for you, state your own weekly capacity and the shortlist is trimmed to it.

How is this different from other LinkedIn Claude skills?

Most are either content tools that write posts and comments, or automation tools that drive a browser or hold a session cookie. This is neither: a research, scoring and relationship-management layer that writes no content and automates nothing, and routes content work to the bundles that already do it well.

Limitations, stated plainly

  • It cannot find people you have no source for. No scraping means discovery volume comes from a conference listing, a team page, a directory or your own connections export — not a LinkedIn search result set.
  • Three metrics are structurally unavailable — profile visits, followers gained, content engagement from new connections — because nothing here reads LinkedIn. They fill from your own analytics export.
  • Per-person content attribution is unavailable. LinkedIn does not expose engager identity to a third party.
  • Audience segment sizes are declared, not counted. LinkedIn gives the account holder aggregate demographics, not a list of people.
  • The scoring weights are a modelling choice, not a measurement. They order your attention against goals you stated.
  • No official LinkedIn API client ships. It needs a Partner Program approval most users do not hold; the integration point is defined and left unimplemented rather than faked.

Works alongside other bundles

This bundle writes no content and optimises no profile, so it does not overlap with content bundles such as sergebulaev/linkedin-skills, nor with company-Page bundles such as chandewardnyanesh/linkedin-company-page-skills. Running all three gives thirty-seven skills with one overlap of substance, documented on both sides.
